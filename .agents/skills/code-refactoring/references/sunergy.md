architecture or capability status. Follow current repository instructions and actual
owners if files move. Core lifecycle procedures and helpers work without this adapter.

## Interpret the curated understanding

The [collaborator overview](../../../../docs/legacy-refactorizacion/README.md) describes
its evidence method. `medido` and `verificado` may refer to AST measurements or source
review rather than execution. Check the measured artifact/tool, revision and scope.
`propuesta` is a design option; `indeterminable` identifies a gap. A complete document
can describe unfinished software. Contract chapters can mix current assumptions
with target requirements; classify each consequential clause.

Recheck actual captures and implementations. Some numerical boundaries may already
have independent outputs while adjacent branches remain missing; do not carry old
blanket statements that all outputs are absent or the whole backend is scaffolded.
Likewise a successful representative capture does not establish full capability,
scientific validity or empirical accuracy. The current status/coverage record and
artifacts determine which gates passed for which inputs/environment.

## Apply at each development stage

- **Assessment/capture:** preserve frozen `legacy/` and inspect side effects before
  isolated runs. UI/helper imports may bring plotting and network/file behavior;
  older helpers delete CWD CSVs or overwrite uploads. Check actual dependencies,
  including PySAM for relevant CEC fitting, instead of assuming a generic Python
  environment or today's lock reproduces the original environment.
- **Refactoring/uplift:** Python owns deterministic/domain calculations, boundaries
  validate external data, and transport/presentation call those owners. Locate
  current modules rather than prescribing filenames or building parallel schemas.
  Refresh generated API consumers from their actual authority when contracts change.
- **Mathematical changes:** coefficient meaning, material/reference conditions,
  irradiance equations, solver/grids, correction methods and RNG semantics require
  explicit versioned decisions. Recommendations/tolerances in curated chapters are
  not automatically accepted defaults. Read the current verification register and
  operation assumptions; preserve compatibility separately from reviewed corrections.
- **Integration/redesign:** source originals, normalized values and fitted parameters
  have distinct identities. Catalog/weather refresh is explicit; saved runs and
  baselines retain hashes. Exercise affected producer/consumer flows and unavailable
  cases. Extend systems/finance/layout only after the relevant project gates; use
  real requirements rather than reserving speculative components.
- **Verification/handoff:** native capture/replay contracts own domain comparisons.
  Portable skill helpers may supplement artifact/test integrity but do not replace
  provenance or scientific checks. Synthetic comparator data test plumbing; original-
  source captures with synthetic inputs may establish software reproduction within
  their stated scope, not weather/measurement or general physical validity.

Use the full [reproduction policy](../../../../docs/reproduction.md) for capture
fields/comparison semantics instead of duplicating its schema. Keep private inputs
and generated experiments in isolated ignored paths; only deliberately reviewed,
redistributable fixtures belong in tracked evidence. Preserve original measurements
and uncalibrated results when evaluating or fitting later models.
