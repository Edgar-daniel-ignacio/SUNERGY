# 005 — Portable refactoring lifecycle and simplification skills

## Objective and scope

Expand `code-refactoring` to orchestrate the full modernization/refactoring cycle
across agent platforms, languages and changing repository structures. Adapt the
provided `code-simplifier` plugin into an independent standard skill for auditable,
practical code. Retain useful plugin routines as portable instructions/tools;
exclude platform-only hooks, UI, telemetry and implicit permissions.

Completion requires usable stage routing (assessment through implementation,
verification, integration/handoff), reusable tested evidence helpers, independently
usable simplification guidance and representative fresh-context trials including
later-stage work and conflicting/incomplete evidence. No production refactor,
dependency upgrade, new scientific decision, baseline replacement, deployment,
  global configuration or changes to the preserved modernization plugin source.
  The simplifier's supplied prompt may be relocated byte-for-byte as provenance.

## Decisions

- Portable core specifies roles, evidence, state transitions and resume semantics;
  agent tools and UI metadata remain optional adapters. Sequential execution works
  when delegation is unavailable. Read stage references only when relevant.
- Reuse one repository task record for goals, contract/rule/delta coverage, status
  and next actions. No fixed analysis/modernized layout or additional memory system.
- Separate runtime/library uplift, behavior-preserving extraction/translation and
  architectural redesign; route each through its actual prerequisites/gates.
- Adapt deterministic output comparison, per-test result comparison and source/test
  integrity checks as Python stdlib CLIs with explicit paths and data-only reports.
  No mtime-based preservation, aggregate counts as test proof, universal numeric
  thresholds, swallowed records, automatic difference approval or `PROVEN` label.
- Simplification is bounded by requested/diff scope and observable behavior. It is
  usable before/after implementation and during review, not unsolicited repo churn.
- Original README declares Apache 2.0 but this copy omits root license/revision.
  Newly author portable implementations from operational methods, retain truthful
  provenance, and do not transplant vendor assets or opaque script bundles.
